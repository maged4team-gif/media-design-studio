# استوديو التصميم التلفزيوني والإعلامي | Media Design Studio Showcase

منصة ويب خفيفة وسريعة ذات واجهة عربية أصيلة (RTL) واستعراض سينمائي داكن، مصممة خصيصاً لاستوديوهات تصميم الهويات التلفزيونية والجرافيك الإعلامي لعرض المشاريع لعملائهم، مشاهدة العروض بدقة عالية، تدوين الملاحظات التوقيتية، واعتماد الأعمال بضغطة زر واحدة.

---

## الميزات الرئيسية

1. **نموذج وصول مخصص بدون تسجيل مستخدمين (Zero Public Registration)**:
   - كل عميل يحصل على رابط خاص فريد (مثال: `/p/x7K29AbC`).
   - حماية الرابط بكلمة مرور مشفرة (Bcrypt).
   - توثيق آمن عبر كوكيز مشفرة ومحمية (`httpOnly`, `sameSite=lax`).
   - تسجيل الملاحظات والاعتمادات باسم العميل تلقائياً بمجرد دخوله الرابط.
2. **معرض مشاريع سينمائي (Cinematic TV Portfolio Grid)**:
   - تصميم داكن فخم (Dark Charcoal & Navy) بلمسات زرقاء وتدرجات ذهبية تلفزيونية.
   - بطاقات مشاريع أنيقة تستجيب للشاشات: 4 أعمدة على الديسكتوب، 2-3 على الأجهزة اللوحية، وعمود واحد على الهواتف.
   - نسبة إنجاز يتحكم بها مدير الاستوديو يدوياً (0% إلى 100%) مع شريط تقدم سلس.
3. **استعراض الوسائط والملاحظات التوقيتية (Timecoded Review Lightbox)**:
   - مشغل فيديو داخلي بدقة عالية بدون الانتقال خارج الموقع.
   - زر مخصص لإضافة ملاحظات عند التوقيت الدقيق للفيديو (مثل: `00:07`).
   - النقر على أي ملاحظة توقيتية ينقل مشغل الفيديو فوراً إلى تلك الثانية.
   - زر اعتماد فوري (معتمد / غير معتمد) يحفظ حالة الاعتماد واسم العميل وتاريخه.
4. **لوحة تحكم إدارية خفيفة وسريعة (`/admin`)**:
   - حماية بكلمة مرور إدارية رئيسية واحدة من ملف البيئة (`ADMIN_PASSWORD`).
   - إضافة وتعديل وحذف وأرشفة المشاريع.
   - رفع الوسائط بالسحب والإفلات (Drag & Drop) لمقاطع الفيديو والصور وحزم التصميم (ZIP, AE, C4D).
   - إمكانية إعادة ترتيب الملفات، تغيير مسمى النسخة (V1, V2, Final)، وإخفاء أو إظهار الملفات للعميل.
   - توليد روابط وصول العملاء بنقرة واحدة وتعيين المشاريع المصرح بها لكل عميل.
5. **مرونة التشغيل الفوري (Dual Data Service)**:
   - يدعم الاتصال بقاعدة بيانات Supabase وStorage تلقائياً عند توفر المفاتيح.
   - يحتوي على نظام بيانات محلي متكامل ومثبت مسبقاً بستة مشاريع تلفزيونية عربية مع رابط تجريبي للعميل «أحمد» يعمل مباشرة دون انتظار تهيئة Supabase.

## التقنيات المستخدمة

- **Next.js 15 (App Router)** & **React 19**

## التشغيل المحلي (Quick Start)

### 1. تثبيت الحزم (إن لم تكن مثبتة):
```bash
npm install
```

### 2. إعداد متغيرات البيئة (DATA_MODE إلزامي):
قم بنسخ ملف `.env.example` إلى `.env.local`:
```bash
copy .env.example .env.local
```

> [!IMPORTANT]
> يجب تحديد `DATA_MODE` صراحة إما `demo` أو `supabase`. عدم تمرير المتغير سيؤدي إلى خطأ إعداد فوري `CONFIG_ERROR` ولن يتم تفعيل الوضع التجريبي تلقائياً.

#### أ. للتشغيل التجريبي المحلي (Local Demo Mode):
```env
DATA_MODE=demo
ADMIN_PASSWORD=admin2027
SESSION_SECRET=media-studio-broadcast-secret-salt-2027
```

#### ب. للتشغيل مع Supabase السحابي (Production / Supabase Mode):
```env
DATA_MODE=supabase
NEXT_PUBLIC_SUPABASE_URL=https://<your-project-id>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<your-anon-key>
SUPABASE_SERVICE_ROLE_KEY=<your-service-role-key>

# في الإنتاج، يجب أن تكون كلمة المرور 10 محارف على الأقل وغير مطابقة للأمثلة المعروفة
ADMIN_PASSWORD=<كلمة-مرور-قوية-للإدارة>

# في الإنتاج، يجب أن يكون مفتاح الجلسة عشوائياً بقوة تشفير وبطول لا يقل عن 32 محرفاً
SESSION_SECRET=<مفتاح-تشفير-عشوائي-32-محرف-أو-أكثر>
```

### 3. تشغيل خادم التطوير:
```bash
npm run dev
```
افتح المتصفح على: [http://localhost:3000](http://localhost:3000)

## خطوات تطبيق ترحيلات Supabase بالترتيب (Migration Execution Order)

عند ربط قاعدة بيانات Supabase الحية، يتوفر مساران للإعداد بحسب حالة قاعدة البيانات:

### المسار الأول: الإعداد الجديد من الصفر (Fresh Database Setup)
إذا كنت تبدأ بمشروع Supabase جديد وفارغ تماماً:
1. نفّذ ملف [`supabase/schema.sql`](./supabase/schema.sql) بالكامل في محرر SQL في لوحة تحكم Supabase. ينشئ هذا الملف كافة الجداول، سياسات الأمان RLS، الإجراء المخزن الذري المحصن `update_access_link_atomic` مع `SET search_path = ''` وصيغة COALESCE المتوافقة، وسلة التخزين المقيدة بحد 500MB ونطاق الامتدادات المسموحة.
2. نفّذ ملف [`supabase/seed.sql`](./supabase/seed.sql) لملء البيانات الافتراضية للمشاريع الستة ورابط العميل التجريبي.

### المسار الثاني: ترقية قاعدة بيانات قائمة تسلسلياً (Sequential Upgrade Path)
إذا كانت قاعدة البيانات مبنية على إصدار سابق، يجب تطبيق ملفات الترحيل في مجلد `supabase/migrations/` بالترتيب التسلسلي الصارم:
1. **الترحيل 001:** [`supabase/migrations/20260908000001_phase1_security.sql`](./supabase/migrations/20260908000001_phase1_security.sql)
   - تفعيل RLS على جميع الجداول وفصل صلاحيات القراءة للمشاريع المنشورة والملفات المصرح بها.
   - إعداد سلة التخزين الخاصة `media-studio-assets` ومنع وصول `anon`.
2. **الترحيل 002:** [`supabase/migrations/20260908000002_phase1_corrections.sql`](./supabase/migrations/20260908000002_phase1_corrections.sql)
   - إضافة أعمدة `cover_storage_path` و `thumbnail_storage_path` لحماية المسارات الأصلية.
   - فرض قيد UNIQUE صريح على `(asset_id, access_link_id)` لعمليات upsert دون تضارب فهارس جزئية.
   - إنشاء جدول `pending_storage_cleanups` لتتبع محاولات تنظيف التخزين الفاشلة.
3. **الترحيل 003:** [`supabase/migrations/20260908000003_phase1_hardening.sql`](./supabase/migrations/20260908000003_phase1_hardening.sql)
   - تحصين الإجراء المخزن الذري `update_access_link_atomic` مع `SET search_path = ''` وتأهيل أسماء الكائنات `public.*`.
   - سحب صلاحيات التنفيذ كلياً من `PUBLIC` و `anon` و `authenticated` وحصرها على `service_role`.
   - إزالة تكرارات الاعتمادات السابقة بالاعتماد على أحدث `updated_at`.
   - تقييد حجم الملفات في سلة التخزين إلى 500MB (524,288,000 بايت) وحصر أنواع MIME.
4. **الترحيل 004:** [`supabase/migrations/20260908000004_fix_coalesce_syntax.sql`](./supabase/migrations/20260908000004_fix_coalesce_syntax.sql)
   - تصحيح صيغة `COALESCE` المتوافقة مع محرك PostgreSQL داخل الإجراء الذري.
   - تجريد استجابة الإجراء الذري من أي أسرار (`password_hash`) وإرجاع كائن JSONB آمن.
   - إعادة تأكيد سحب الصلاحيات من `PUBLIC` و `anon` ومنح `EXECUTE` لـ `service_role` فقط.
